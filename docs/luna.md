# LUNA 二进制组件

LUNA 后端以版本化静态库随仓库提供。构建只读取当前宿主平台的本地归档，
不下载组件、不需要额外账号或源码仓库。实现源码与内部数值参考不在本仓库。

## 文件与平台

- `qemu/include/lisem/luna.h`：版本化 C ABI。
- `qemu/luna/<system>-<arch>/liblisem-luna.a`：普通机器码静态库。
- 同目录 `manifest.json`：版本、ABI、目标、库 SHA-256 与接口头文件 SHA-256。

目标名称使用 `darwin`、`linux`、`windows` 和 `aarch64`、`x86_64`。
每个平台单独构建，不跨架构混用。macOS 最低 15.0；Linux 的库使用 GLib
和系统 C 运行库；Windows 与 QEMU 使用一致的 MSYS2 CLANGARM64/UCRT64 ABI。
静态库成功链接不等于该平台整机已通过音频、网络或交互验收。

`tools/build_qemu.py` 在配置 QEMU 前校验目标、ABI 和两个哈希。组件缺失或
校验失败会明确停止，不使用占位实现、不静默下载或退回其它版本。

## 接入契约

`qemu/hw/riscv/arcs_luna.c` 是 QEMU 接入层。每个设备创建独立的不透明上下文，
不读取内部结构，也不解析内部命令参数。库只通过 `LisemLunaHost` 调用宿主。

- 内存回调使用 guest 地址和宿主缓冲，必须经过 QEMU 地址空间及其错误检查。
  不把 guest 地址直接转成宿主指针，不绕过总线写回与代码失效。
- SHA-256 回调返回 64 个十六进制字符加终止符；处理每次请求的实际字节。
- 定时回调把相对延迟转换为 QEMU 虚拟截止时间。只在到期事件调用
  `lisem_luna_complete`；计算已经完成不代表可以提前交付结果。
- 复位取消定时事件和未完成输出；不能在取消后调用旧完成回调。
- `lisem_luna_read_safe` 只声明无副作用的状态读取。是否允许加速仍由 QEMU
  的访问权限、调试状态及计数策略决定，不能绕过 GDB/PMP 的回退路径。
- `fatal` 回调记录错误并终止当前运行，不能返回成功继续执行。
- 上下文与回调在设备执行线程上串行使用；回调表复制后，其 opaque 对象必须
  保持有效。销毁前停止所有定时回调，不跨实例共享状态。

ABI 不匹配必须拒绝创建。新增字段、改变函数签名或结构布局需要发布匹配
的新 ABI 与全部目标库；不能只修改公开头文件强行编译。

## 更新与验收

维护者导入同一组件版本的全部平台归档、manifest 和接口头文件，作为一次
完整提交。版本更新不得混入源码、调试文件、LTO bitcode 或内部来源元数据。
保留 Linger 的 Apache-2.0 归属和许可；它的相关系数用于组件实现。

更新顺序：

1. 核对所有目标 manifest 的版本和 ABI 一致，核对库与头文件 SHA-256。
2. 运行 `make test`，重新构建 QEMU，运行 `make check-qemu`。
3. 使用实际发布 LPK 验证启动、推理、持久化和复位；再验证连续录播、AEC
   参考及宿主网络同时运行。测试命令见 `docs/development.md`。
4. 用相同输入串行比较更新前后的完整报告、UART、屏幕、DAC 和报文输出。
   数值或兼容行为确需变化时，说明预期差异；不修改参考结果掩盖回归。
5. 在每个声明支持的平台做原生构建和实际运行，再更新发布包。

组件异常优先保留版本、宿主平台、可复现输入、虚拟时序、寄存器访问和错误
日志。共享复现材料前移除用户凭据及业务数据。不要在接入层按固件地址、
微程序指纹或业务场景伪造结果来绕过组件问题。
