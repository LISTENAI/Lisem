# 架构

Lisem 由共享 Rust 核心、桌面与自动化入口、QEMU 运行后端和宿主组件组成。
芯片、板型和外接器件分别建模；固件通过模拟的 CPU、总线和控制器访问硬件。

## 模块职责

| 模块 | 职责 |
| --- | --- |
| `crates/core/` | 板型校验、实例库、存储、运行控制和宿主数据通道 |
| `crates/cli/` | 命令行、原生管理 RPC 与 MCP stdio 服务 |
| `python/` | 同步自动化 SDK、pytest 集成及固件示例 |
| `desktop/` | 实例管理、设备交互和状态呈现 |
| `qemu/` | CPU、芯片、控制器、器件及虚拟时间执行 |
| `native/` | 宿主音频、摄像头和网络接入 |
| `boards/`、`chips/` | 板型与芯片描述 |
| `assets/` | 固定 ROM、LUNA 二进制及校验清单 |

GUI、CLI 和 MCP 共用核心及实例管理协议。无头入口不链接窗口系统，宿主网络
和音频通过运行选项启用。产品包携带运行组件和非系统依赖，通过相对路径发现
资源；构建与打包方式见[构建与维护](development.md)。

随包 Python SDK 由 `lisem python` 选择用户解释器加载，启动配套 CLI 的原生管理会话，连接带鉴权的 worker 端点，按实例和
运行标识执行控制。临时设备使用所有权日记管理存储和清理；交付结果未知时保留
资源并报告。同步观察共用单调时钟截止时刻，覆盖锁等待、RPC 及轮询。固件启动
步骤与业务判据由示例或测试工程维护。原生应用独立运行，Python 自动化使用用户解释器与虚拟环境；SDK 源码及标准包元数据随应用交付。

## 芯片、器件与板型

芯片模型提供 CPU、地址空间、片内控制器、时钟、中断和 PinMux。独立器件模型
提供器件端口、协议及状态，不依赖某款芯片的 SoC 类型。芯片适配层把控制器、
总线和焊盘接入公共装配层。

板型 JSON 以 `devices` 选择器件，以 `nets` 描述接线，以 `links` 连接像素、
亮度等数据接口。`inputs` 声明外部可控信号的类型、范围、默认值和连接点。
内置板型和导入板型共用校验与装配路径，格式见[自定义板型](boards.md)。

核心校验原始描述，并派生前端控件和后端装配计划。实例保存原始描述，GUI
根据可用器件显示操作入口。未知模型、端口、参数和不支持的接线在装配前报错。
固件负责设置控制器和 PinMux；总线传输取决于实际启用的路由、时钟和器件状态。

板型更新须持有实例库及受影响实例的存储锁，并校验芯片和存储布局兼容性。
使用该板型的实例在下次上电时装配新配置，Flash、OTP 和设备身份保持独立。

## 实例与进程

实例持久化 Flash、OTP、硬件描述及宿主设置。每个活动实例由独立 Rust worker
管理存储锁、QEMU 子进程和宿主组件。GUI 与命令行是管理客户端，可以连接
同一个 worker；串口转发和后台运行独立于 GUI 窗口。

`run` 持有前台运行，中断时停止该轮执行；`start` 将运行留在后台。关闭窗口
或退出 GUI 保留实例与 UART 端点，显式下电停止 QEMU，`shutdown` 关闭 worker。
后台进程报告自身的编译身份，QEMU 身份按启动轮次记录。

运行期间持有存储锁。QEMU 继承存储保护，使控制进程异常退出后，仍在运行的
QEMU 不会与其它写入者同时修改 Flash。POSIX 使用共享同一打开文件描述的锁，
Windows 使用禁止共享并由子进程继承的文件句柄。

## 管理与控制

管理端点使用本机回环 TCP 和随机令牌，端点信息位于实例目录。控制请求携带
实例身份和运行标识，过期请求被拒绝。运行中的设置变更在后端确认后持久化。

worker 经 QMP 控制 QEMU，UART 使用独立连接。请求和回复有大小及时间上限；
待确认事务保留原请求与已接收数据，恢复时继续同一事务。确认结果未知时，
状态明确标为待确认或失败，后续变更受事务状态约束。

外设输入的选择与连续数据传输分开。控制通道用于选择来源、确认代际和查询
状态；高频音视频走有界共享内存或原生管道，避免阻塞管理请求。

## 虚拟时间

CPU 执行推进指令计数和虚拟时间，外设依据功能时钟安排事件。完成事件负责
发布输出、写入内存和更新 IRQ；时钟门控、复位及取消处理待执行事件。
计算可在宿主提前完成，结果按虚拟完成时刻交付。

CPU 调度协调各核的执行进度与外设事件。计数器读取、状态查询和截图不推进
虚拟时间。运行预算分别限制虚拟时间、指令数和宿主等待；暂停与暖复位保持
各自的时间轴语义。

交互式运行使用宿主节拍约束虚拟执行的领先量。慢宿主通过等待和背压影响
吞吐，不跳过固件指令或外设事件。功能时钟模型不包含物理缓存、流水线、
电气传播和射频延迟，不能用于硅片逐周期性能验证。

## 信号与总线

外部数字量驱动板型声明的网络，电压经板级分压送到 ADC 输入。ADC 依据固件
配置的参考、采样和转换过程产生数据。输入的业务含义由固件解释。

按键、触摸和自动化输入经过器件及中断链路。长按和连按序列由虚拟时钟安排，
保留运行与序列标识；取消、复位和下电释放自动按键。手动操作取消对应序列后
生效。

LED、功放和信号探针从接线派生观测元数据，界面读取驱动状态、电平和有效
极性。宿主输出开关与板级器件状态分别表示。

控制器、器件和总线各自管理状态。器件识别、数据传输完成和固件业务结果是
独立的可观测结果；支持范围由具体模型及芯片接线决定。

## 显示、音频与摄像头

显示器件产生的画面经 QEMU `DisplayChangeListener` 发布到有界共享帧通道。
界面读取最新完整帧，慢界面不阻塞 CPU。截图的像素、序号和时间戳来自同一帧，
并携带运行标识。

音频采样经模拟控制器和 DMA 到达固件；DAC 输出与宿主播放分离。原始样本、
虚拟时间戳、静音及功放状态保留在数据通道中，宿主播放按实际输出时刻生成
参考时间映射。板型声明的回采连接向 ADC 提供电参考，AEC 算法由固件执行。

音频回调只处理内存及原生队列。播放欠载、重新缓冲和麦克风过载通过计数与
状态公开。实时麦克风可以同步跳过积压的输入与参考；显式诊断侧录使用无损
契约，积压、速率变化或运行中断明确报错。

摄像头来源提供传感器场景。核心按板型的安装方向映射并等比裁剪，图片与
宿主摄像头共用该路径。传感器输出经总线、FIFO 和 DMA 送往固件。

实时帧使用有界最新帧通道和源代际。帧开始时锁存像素及采集配置，整帧保持
一致；丢帧、重复帧、断开和首帧状态可查询。来源切换在首帧与后端确认后保存，
失败保留明确错误。下电、清除来源和运行时退出释放宿主采集。

宿主组件按平台接入系统服务：

| 通道 | macOS | Windows | Linux |
| --- | --- | --- | --- |
| 音频 | AudioQueue | WASAPI | PulseAudio 协议 |
| 摄像头 | AVFoundation | Media Foundation | V4L2 |
| 共享内存 | `shm_open` / `mmap` | `CreateFileMapping` | `shm_open` / `mmap` |
| UART | PTY | 回环 Raw TCP | PTY |

设备选择、权限和格式限制见[使用说明](usage.md)。

## 存储与外部连接

Flash 和 OTP 按实例持久化，UID 从 OTP 读取。LPK 导入按包内布局写入 Flash；
暖复位保留 Flash 的实际修改。NOR 写入使对应代码缓存失效。固定芯片 ROM
作为产品资产校验并链接到运行后端，独立于可擦写的实例存储。

SD 镜像使用可写 raw 块后端和独占写锁。固件执行命令、DMA、分区及文件系统
操作。介质状态和机械检测引脚分别建模，拔出时取消未完成传输并报告相应错误。

UART 按实例和通道提供稳定端点。字节保持原样，输入、输出及观察历史分别
管理，跨运行输出按顺序交付。数据背压受内存容量限制，观察游标溢出明确报告。

Wi-Fi 环境按实例保存。逻辑热点经 MAC 帧参与扫描、认证和关联，安全热点
执行密钥握手和帧加解密。宿主网络桥接承接外网转发；热点是否可见、链路是否
建立及外网是否可达是独立状态。固件运行自己的网络栈和业务协议。

BLE 虚拟中心端与固件 peripheral 交换实际广播、链路 PDU 和 ATT 请求响应。
公共中心端模型负责虚拟定时、链路确认、重传及 L2CAP 重组，芯片适配层连接
控制器收发描述符和 IRQ。当前 Arcs 路径支持 legacy 1M、单连接和明文 GATT；
DM AES 通过芯片寄存器及 EM 执行，结果在虚拟完成事件写回。

共享核心维护 GATT 操作、实际 ATT 错误、连接所有权及有界事件，CLI、MCP 和
Python SDK 使用同一控制入口。控制绑定当前运行及连接身份，取消停止剩余
传输，已结束的同一连接可确认清理。宿主查询观察状态，空口排程由 QEMU
虚拟时钟推进。

固件管理广播、属性权限及应用协议；调用工程负责业务报文和结果判据。
BLE 事件保留原始字节、虚拟时间及游标丢失信息，原始链路 trace 显式启用。

USB 主机执行真实枚举和端点传输。ADB TCP 桥接发现固件暴露的接口，适配
消息边界并保留双向背压；shell、日志和文件操作由固件执行。断开、复位及
重枚举取消旧传输。板上的 USB 角色控制器通过自己的总线和引脚反映连接状态。

## 组件与故障观测

LUNA 组件通过版本化 C ABI 接入，各实例使用独立上下文。内存访问经过 QEMU
地址空间，结果在虚拟完成事件写回，复位取消未完成输出。组件校验和维护契约
见 [LUNA 二进制组件](luna.md)。

正常运行使用有界内存，不持续保存音视频、UART 或网络包。显式诊断采集按
请求生成记录，错误与容量上限可观测；固件对 Flash、OTP 和 SD 的实际写入
按存储语义保留。

未实现的模型行为报告具体错误并停止相应操作。构建身份、运行标识、原始
UART、帧元数据、外设状态和计数用于区分执行、传输及宿主接入问题。构建输入
与产物哈希不一致时，运行入口拒绝使用过期组件。
