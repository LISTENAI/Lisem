# 固件自动回归

目标是执行用例并给出可以核验的结果。先读取用例和固件相关说明，确认原始
固件、板型、输入、业务环境及预期，再选择模拟器操作。

## 准备可执行的用例

对每项用例明确前置状态、刺激、观察点和通过条件。根据固件说明准备素材、
文件系统、服务器及业务配置，按需使用现有发布资产、构建入口和测试服务。
在授权范围内自行补齐并验证这些条件；仍无法执行时，记录缺少的条件、
已尝试的准备方式及所需权限或能力。云服务、绑定方式、串口命令及按键规则
以待测固件为准。

保留固件和素材哈希、板型、构建身份、实例及运行标识。按用例需要选择新实例
或持久化状态；例如首次初始化、升级及掉电恢复具有不同前置条件。
测试过程中保持待测固件行为不变，外部刺激通过模拟器提供的输入施加。

涉及聆思平台时，配合 `ling` skill 准备或检查应用、设备授权、OTA 测试资源
及业务配置；也可用其 TTS/ASR 能力准备或核验语音素材，通过 request/trace
检查云端响应和会话证据。按任务读取其对应参考。
环境未提供该 skill 时，可从 `ling --help` 发现当前 CLI 能力；缺少登录、
权限或必要操作入口时说明具体条件。直接调用云端可用于隔离问题，完整端云
用例仍须由模拟器中的原固件发起并核验结果。

## 输入及环境夹具

- **WAV**：准备 16 kHz 单声道 PCM16，并检查帧数、时长和有效内容。
  语音用例需有可辨识的语句；传输测试的波形不能代替语音识别验收。
  输入由固件 ADC 消费，CLI 阻塞到完成或取消；MCP 提交后观察同一序列。
  ADC 未开启不等于注入完成。系统麦克风与 WAV 注入不能同时占用输入。
- **摄像头**：按用例准备场景图片或获得授权的宿主摄像头。
  确认来源已应用，再由固件触发采集。分别验证用例要求的取景、图像处理或
  后续业务结果。
- **SD**：准备可写 raw 镜像，大小为 8 MiB～32 GiB 的二次幂。
  按固件支持的格式建立分区和文件系统；空白零填充文件不等于格式化空卡。
  测试目录层级、文件格式和文件名时，把相应文件写入镜像并在宿主检查。
  挂载前卸载宿主文件系统，使用独立镜像副本；同一镜像只由一个写者使用。
  区分卡被识别、文件系统挂载、文件读写、应用处理和写回持久化。
  涉及文件索引或筛选时，准备匹配与不匹配的文件，核对实际结果是否排除
  反例。检查固件实际读取、上报的文件名、元数据或内容；文件包含某字段，
  不代表后续处理链路已取得该字段。
- **Wi-Fi**：配置用例需要的 SSID、安全方式、密码、RSSI 和互联网状态。
  热点可用性、关联授权与公网访问是不同观察点。密码错误或断网用例须验证
  真实连接结果，不能只查看配置值。
- **外部信号**：从当前板型发现可控输入的标识、类型、单位、范围和默认值。
  使用板型定义的数字量或模拟量，电压等数值按声明的测量端填写。
  运行中修改后确认应用状态，再检查固件实际采样与响应；物理量到业务状态的
  换算、阈值及延时以待测固件为准。未暴露的输入不能靠修改固件内存代替。
- **固件升级**：准备起始固件、兼容的目标包及固件所需的获取入口。
  核对包的版本、布局、校验及签名要求；按任务从现有资产获取或使用原项目
  构建流程生成测试包。服务地址、设备筛选和升级确认方式按待测系统配置。
  记录升级前后版本及可核验的存储结果，不能只凭下载完成判断升级成功。
  对中断恢复分别记录中断发生在下载还是写入，以及恢复是否需要重启、
  再次确认或重新下载，按用例要求的恢复方式判定结果。

## 时序与连续观察

短时动作使用 `lisem_events` 或 CLI `events`：先布置未来 UART 字节条件或
绝对虚拟时间，再提供触发刺激。匹配原始字节，不依赖日志渲染颜色或排版。
条件有明确过期时间；普通 WAV 注入可用于触发已经布置的 UART 条件。
手动按键接管会取消待执行自动动作，执行期间检查是否有其他输入接管。
`dispatched` 只表示动作已发出，继续跟踪按键、音频序列和业务结果。

数字 IO 时序先用 `signal-trace ID` 或 `lisem_signal_trace` 的 `list` 查询信号源，
按返回的源 ID 或网络名选择采集范围。用当前 `run` 启动 `start`，保存返回的
`capture`；`read` 从 `after=0` 开始，再用 `next_cursor` 分页。每条事件包含
`virtual_ns`、逻辑电平和 `driven`；`initial=true` 是采集开始时的状态，
不能当作之前发生的边沿。按相同源计算周期、高低电平时长及先后关系。

采集在复位或下电时结束；`stop` 可提前结束，结束后继续读取剩余事件。
检查 `lost_events`、`has_more` 与结束状态：游标溢出、`interrupted` 或
`unknown` 都不能作为完整时序证据。容量有上限，长时采集须持续分页并显式
保存需要的结果。数字事件反映模型产生的电平变化；物理引脚频率、模拟波形
和未生成边沿的总线传输需另有测量依据。

连续开关机、升级及长时测试，启用 UART 原始接收归档并保持读取。
旁路 `uart_read` 不消费终端字节；它有历史容量上限，不能承担长期接收。
不要同时给同一端点接两个终端读者。记录运行切换及对应字节边界，保留
CRLF、ANSI 和非文本字节；分析副本可另外解码。

用状态中的剩余虚拟预算和宿主期限判断可运行时间。电源用例分别观察模拟
进程、板级电源信号及固件状态，结合日志和画面判定。
持续运行用例按要求的时间尺度执行，记录实际时长和未执行部分。
时长和先后关系使用同一时钟域内的单调时间；校时可能改变固件日志墙钟。
结合运行标识区分虚拟时间、宿主单调时间与日历时间，重启后的计时另行记录。

音频计数和非零样本用于定位活动，不能证明语音内容、音乐连续性或音质。
需要时显式用 `audio-output --capture` 侧录 WAV，检查声音、时序、静音段和
错误状态。截图核对 `run`、帧序号及时间；相同帧不能当作新的页面反馈。

## 判定与交付

每项结果区分：通过、观察到失败、外部条件阻塞、尚未执行。若前置条件失效，
先修复后重跑，不将无效尝试计为固件失败。不能只凭一次工具返回成功，或
因为存在对应工具，就把完整功能标为通过。

执行结果与原因分别记录。失败可来自模拟器、固件、外部服务、配置或用例
预期差异；证据不足时保留待定。按任务需要结合日志、状态、源码或最小复现
定位问题，注明原因的证据与不确定性；独立复现须记录与原场景的差异。
用例与实现不一致时保留双方行为及结果，不擅自改写预期来判通过。

给出操作、观察结果及证据位置。失败保留触发前后 UART、截图、相关音视频、
运行状态和素材身份；区分已证实原因与待验证推测。只停止本次测试拥有的
录制、输入和运行，按测试约定恢复临时服务配置及存储，保留任务要求留存的
实例及数据。清理测试配置时不覆盖其他使用者的变更。

报告逐项记录执行版本。复用历史结果时，标明其版本及未重跑的范围。
总数按实际用例行统计，核对汇总范围和各状态数量；全量通过率以全部用例
为分母，已执行项通过率以通过与失败之和为分母。
