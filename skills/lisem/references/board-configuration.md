# 从原理图创建板型

将原理图中的硬件组合映射为 Lisem 板型 JSON，交付可校验、可导入的描述及
实际验证结果。先发现当前安装版本的能力，再选择模型和接线。

## 确定硬件与模型

读取原理图的相关页、跨页网络及连接器定义。PDF 中的引脚编号、交叉线、
连接点和方向需要结合页面图像核对，文本提取可用于检索。结合 BOM 确认实际
装配料号、选配与未装器件；资料冲突或连接器外接物料不明时，记录具体疑点，
继续处理能确定的部分。

通过当前安装的程序取得器件目录，已知类别或料号时直接筛选：

```sh
lisem board-models --category CATEGORY
lisem board-models --model MODEL
```

将占位值换成所需类别或型号。MCP 使用 `lisem_catalog` 的 `category` 和
`model` 参数。类别从返回的 `categories` 发现；需要完整目录时用无筛选的 MCP
调用或 CLI `board-models --details`。分类结果默认提供简短型号列表，按需使用
`details=true` 或 `--details` 展开。型号查询返回完整详情，采用返回的规范
`model` ID 写入板型；`found=false` 表示当前筛选下没有对应模型。

读取选定模型的 `signals`、`data_signals`、`interfaces`、`parameter_schema`
和 `constraints`，确定必需端口、器件侧信号方向、总线地址、参数默认值及组合
条件；扩展器的模拟输入见 `analog_inputs`。模拟器器件模型通过这个目录查询，
宿主摄像头场景来源通过摄像头设备枚举工具选择。

生成板型前，用 CLI `lisem board-models --schema` 或 MCP
`lisem_catalog(schema=true)` 取得 `board_schema`、`chips`、`wiring` 和参考
板型。`wiring` 给出引脚与可用路由，`boards[].definition` 可作为配置起点。
这些内容随安装包提供；参考板用于查阅模型组合，目标接线仍以硬件资料为准。
以查询的构建身份和实际返回内容记录版本，按帮助和工具 schema 使用接口。
版本缺少必要查询能力时，按任务允许的范围更新工具，或明确保留信息缺口。

整理与模拟有关的信息，并保留原理图页码、位号或网络名作为核对依据：

- 芯片型号、存储容量及封装引脚；将物理脚号转换为该芯片描述中的端口名。
- 器件型号、地址、地址绑带及协议版本；固定固件的扩展器按协议对应的模型选择。
- 总线的每根信号、片选、复位、中断、使能、上下拉和有效电平。
- 扩展器各引脚到外设的连接，以及扩展器本身到主芯片的总线连接。
- 显示可见区域、屏幕与摄像头安装方向；原理图未体现的机械信息另行确认。
- 外部可控输入、测量端、单位、范围和分压比例；按电阻连接方向计算 ADC 端电压。

仅在协议和行为有依据时采用兼容模型。缺少芯片、器件或接线能力时，说明
无法表达的具体部分及其影响，在现有能力范围内完成可验证的部分。

## 生成与校验

按取得的 schema 生成独立 ID 的 JSON，并结合各型号的参数 schema，组织：

- `chip` 和 `storage` 选择芯片及持久存储配置。
- `devices` 声明模型、参数和可选标签；器件 ID 在板型内保持稳定。
- `nets` 使用原理图网络名连接 `器件ID.端口`，包括扩展器端点和必要上下拉。
- `links` 按端口类型连接像素、亮度等数据接口。
- `inputs` 将需要操控的外部网络声明为类型化输入，注明物理单位与默认值。

板型描述固定接线，固件负责控制器与 PinMux 配置。移动某根接线时，核对
目标引脚的路由能力和固件实际配置；配置校验成功不能证明固件已使用新引脚。
器件端口、参数及连接能力以模型为准，遇到校验错误应修正描述或补齐模型。

先在独立设备库中校验和导入，例如：

```sh
lisem --data-dir ./board-check board-validate ./board.json
lisem --data-dir ./board-check board-import ./board.json
lisem --data-dir ./board-check create --board my-board --lpk ./firmware.lpk
```

将 `my-board` 换成 JSON 中的 ID，固件导入方式按实际格式选择；MCP 可使用
`lisem_board_validate`、`lisem_board_import` 及实例创建工具。检查校验返回的
器件、按钮、指示和接线是否与提取的硬件信息相符。更新同 ID 板型会影响使用
它的实例，操作前确认范围并将相关实例下电，保留已有 Flash、OTP 和 UID。

## 用原固件验证

运行目标硬件的原始固件，核对启动、存储容量及逐项外设行为。按已装器件和
任务需要准备摄像头场景、音频、SD 镜像或网络环境；功能回归的准备和判定见
[固件自动回归](firmware-regression.md)。

区分器件识别、数据链路和业务结果：例如屏幕核对方向、颜色和完整可见区域，
摄像头核对实际采集画面，按键核对按下与释放，电压输入核对 ADC 采样及响应。
`status` 中的指示和 GPIO 是状态快照，连续输出时序须有对应的边沿采集证据。

交付板型 JSON、硬件映射依据、校验结果和运行证据，列明未建模、缺少外部
条件及尚未验证的部分。缺少目标固件时可完成配置验证，运行兼容性保持未验证。
